# Git 使用规范

## 提交说明规范

- 使用 Git 管理项目版本。
- 提交信息遵循 Conventional Commits。
- 提交信息格式为 `type(scope): description`，type 与 scope 部分使用英文，description 部分使用中文。

### 部分特殊提交说明规范

文档相关提交说明统一为：docs(涉及文档): 新增/更新涉及文档。

如果涉及到被 AGENTS.md 引用的文档，不单独列出具体文档，而是将提交说明统一为：docs(agents): 新增/更新 AGENTS.md 相关文档/及其相关文档

例如：
- docs(readme): 新增 README.md
- docs(agents): 更新 AGENTS.md
- docs(agents): 新增 AGENTS.md 相关文档
- docs(agents): 更新 AGENTS.md 及其相关文档

## 提交分组规范

- 优先以文件所在目录作为划分 scope 的依据。
- 同一 scope 内，继续根据变动是否属于同一业务进行拆分。
- 不同 scope 的变动原则上应分别提交；同一 scope 下属于不同业务的变动也应分别提交。
- 每次提交只包含一个边界清晰的变动范围，避免将无关变动合并到同一次提交中。
- 不得为了凑成更少的提交次数而合并不同目录或不同业务的变动。

## 本地操作权限

- 允许执行仅影响本地 Git 仓库的操作，包括查看状态、差异、提交历史、创建本地提交等。
- 如果任务收尾后认为本轮任务的执行结果值得创建一次 Git 提交，必须使用 `ask_user_question` 询问用户是否提交。
- 只有用户明确同意后，才能执行 `git add` 和 `git commit`。
- 用户未明确同意、拒绝提交或未作出答复时，默认不提交。
- 提交前必须检查 `git status` 和具体变更内容。
- 不得擅自修改、覆盖或删除用户已有的本地提交历史。

## 远程操作权限

- 严禁执行任何涉及远程仓库的操作。
- 禁止执行 `git push`、`git pull`、`git fetch`、`git clone` 等远程交互命令。
- 禁止通过 Git 命令、脚本、第三方工具或其他方式间接执行远程仓库操作。
- 即使用户要求执行远程操作也不得执行，仅允许向用户提供相关 Git 命令并由用户自行执行。
- 远程仓库的同步、推送及其他远程管理操作均由用户自行完成。

## 提交过程

1. 检查当前暂存区的变动，并制定完整的提交拆分方案；提交方案必须逐项列出：
    - 提交说明：该次提交的具体说明。
    - 涉及文件：该次提交包含的完整文件列表。
2. 将完整的预计提交方案交由用户审查，并使用 `ask_user_question` 征求用户意见；在用户明确批准方案之前，禁止执行任何提交操作。
3. 仅在用户明确批准后，才能按照批准的分组和顺序执行提交。
4. 完成后，检查工作区状态、汇报实际提交记录，并说明是否与批准方案完全一致。
