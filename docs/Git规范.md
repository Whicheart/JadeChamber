# Git 使用规范

- 使用 Git 管理项目版本。
- 提交信息遵循 Conventional Commits。
- 提交信息格式为 `type(scope): description`，type 与 scope 部分使用英文，description 部分使用中文。
- 每次提交应聚焦于一个明确的修改目的。

## 本地操作权限

- 允许执行仅影响本地 Git 仓库的操作，包括查看状态、差异、提交历史、创建本地提交等。
- 如果任务收尾后认为本轮任务的执行结果值得创建一次 Git 提交，必须使用 `ask_user_question` 询问用户是否提交。
- 只有用户明确同意后，才能执行 `git add` 和 `git commit`。
- 用户未明确同意、拒绝提交或未作出答复时，默认不提交。
- 提交前必须检查 `git status` 和具体变更内容。
- 不得擅自修改、覆盖或删除用户已有的本地提交历史。

## 远程操作权限

- 严禁执行任何涉及远程仓库的操作。
- 禁止执行 `git push`、`git pull`、`git fetch`、`git clone` 等远程交互命令。
- 禁止通过 Git 命令、脚本、第三方工具或其他方式间接执行远程仓库操作。
- 即使用户要求执行远程操作也不得执行，仅允许向用户提供相关 Git 命令并由用户自行执行。
- 远程仓库的同步、推送及其他远程管理操作均由用户自行完成。
