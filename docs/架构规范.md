# 架构规范

## 项目架构

采用 Layer-based 架构。

```text
src/
├── api/           #负责 HTTP 请求和 API 接口封装。
├── assets/        #存放图片、图标等静态资源。
├── components/    #存放可复用的通用组件。
├── composables/   #存放可复用的组合式逻辑。
├── layouts/       #存放页面级布局。
├── router/        #负责路由定义和配置。
├── stores/        #负责跨组件共享状态。
├── styles/        #负责全局样式及设计变量。
├── types/         #统一存放 TypeScript 类型定义。
├── utils/         #存放通用工具函数。
├── views/         #存放页面级组件。
├── App.vue
└── main.ts
```

目录及文件按实际需求创建，不提前预设大量页面或业务模块。

## 组件设计

- 遵循单一职责原则。
- 优先复用，必要时再抽取。
- 避免组件之间产生不必要的强耦合。

## 状态管理

- 使用 Pinia 管理跨组件共享状态。
- 组件内部的局部状态优先使用 Vue 自身的响应式能力。
- 按需创建 Store，避免过度使用全局状态。

## 数据请求

- 统一使用 Axios。
- API 请求集中封装在 `src/api/`。
- 页面不得随意直接创建 HTTP 请求。
- 统一处理请求异常。
- API 接口需要记录用途、请求参数及必要的响应类型。
- API 定义以 OpenAPI JSON 为主要依据。

## 数据类型

- TypeScript 类型统一存放在 `src/types/`。
- 根据 OpenAPI Schema 定义 API 类型。
- 不得凭空猜测或编造数据结构。
- TypeScript 类型检查属于编译期检查，不代表运行时数据校验。

## 路由

- 使用 Vue Router。
- 路由配置集中管理。
- 页面按实际需求创建，不预设业务页面。

## 错误处理

- 建立清晰、一致的错误处理方式。
- 禁止静默吞掉异常。
- 必须保留必要的错误上下文，便于排查问题。

## 环境配置

### 环境变量规范

- 使用 `.env` 文件管理项目环境变量。
- 根据环境需要使用 `.env.development`、`.env.production` 等环境文件。
- 环境变量命名使用大写字母和下划线，例如 `VITE_API_BASE_URL`。
- Vite 客户端需要读取的环境变量必须使用 `VITE_` 前缀。
- 通过 `import.meta.env` 读取环境变量，禁止在代码中硬编码环境相关配置。
- `.env` 及包含真实配置的环境文件不得提交到 Git。
- `.env.example` 只记录变量名称和必要说明，不填写真实密钥、密码或敏感信息。
- 新增环境变量时，同步更新 `.env.example`。
