# UI/UX 设计规范

## 设计系统

建立统一设计系统，统一管理：

- 颜色
- 字体和字号
- 间距
- 圆角
- 阴影
- 边框
- 通用组件视觉规范

## 全局字体规范

全站所有页面、组件及 UI 元素必须统一使用 `HYWenHei-85W` 字体，不允许使用其他字体。

- `HYWenHei-85W` 是项目唯一允许使用的字体，必须作为全局默认字体，并确保所有页面和组件继承该字体。
- 任何位置均不得自行指定、引入或使用其他字体，包括但不限于局部 CSS、组件样式、第三方 UI 组件样式及内联样式。
- 只有在 `HYWenHei-85W` 字体加载失败时，才允许回退至系统基础字体。
- 不得设置其他指定字体作为备用字体，不得使用其他 Web 字体、装饰字体或第三方字体作为回退选项。
- 不得因为页面、组件、设备、屏幕尺寸或设计效果的不同而使用其他字体。
- 新增或修改样式时，必须检查是否引入了其他字体；发现违反本规范的字体声明时，应修正为统一字体规范。

## 响应式布局

- 必须支持桌面端和移动端。
- 不得只针对单一屏幕尺寸开发。
- 页面布局应适配不同屏幕宽度。

## 交互原则

- 适度使用动画。
- 避免过度动画和无意义的视觉效果。
- 保证交互反馈清晰。

## 无障碍与交互规范

### 屏幕阅读器支持

- 本项目不主动开发或增加额外的屏幕阅读器适配功能。不得为了满足屏幕阅读器需求而擅自增加 ARIA 属性、辅助播报、隐藏辅助文本或其他额外功能。
- 进行任务实现的过程中，不得仅为了增加 ARIA 属性而添加无实际需求的无障碍标记。

### 键盘操作

应当保证页面现有可操作元素能够通过键盘正常使用。

- 用户可以通过 Tab 键在可操作元素之间移动。
- 按钮、链接等元素应保留正常的 Enter 或 Space 键操作行为，不得无故破坏浏览器原生交互。
- 当前获得键盘焦点的元素需要具有清晰可见的焦点样式，例如边框、高亮或轮廓。
- 不额外设计键盘快捷键。
- 筛选选项不需要额外实现方向键切换。

不得为了实现键盘操作而引入不必要的自定义键盘事件或复杂交互逻辑。

### 图片与内容异常处理

图片需要具有可靠的加载失败处理机制。

- 图片加载失败后，应能够通过文字识别原本展示的图片。
- 纯装饰性图片、背景图案和分隔图案不得产生多余的屏幕阅读器播报。

注意区分图片的视觉失败与屏幕阅读器描述：项目需要的是图片加载失败后的可见替代内容，不需要额外添加图片的语音描述。

### UI 动画与样式规范

尊重操作系统的减少动态效果设置。

- 当用户启用了系统的减少动态效果设置时，应关闭或减弱页面中非必要的动画。
- 优先使用 CSS 的 `prefers-reduced-motion` 媒体查询实现。
- 不得因为减少动态效果而影响页面基本功能。

### 执行要求

- 不得为了满足无障碍规范而擅自修改项目已有的业务交互。
- 如果某个组件确实需要额外的辅助属性或交互支持，但本规范没有明确规定，必须使用 `ask_user_question` 询问用户，不得自行决定。
- 本规范只约束无障碍相关功能及减少动态效果，不代表可以忽略正常的页面结构、交互逻辑和 UI 样式要求。
