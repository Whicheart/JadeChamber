# 文档规范

## README 规范

### README 的定位

README 是项目面向人类读者的主要入口文档，主要服务于：

- 初次接触项目、希望了解项目的读者；
- 希望运行和使用项目的使用者；
- 希望了解技术栈、参与项目开发的开发者。

README 的核心目标是让读者快速理解项目是什么、能做什么、如何运行，以及到哪里获取进一步的信息。

README 不是项目内部所有知识的汇总仓库，也不是其他项目文档的副本。

### 内容编写原则

- 简洁、准确、易于阅读，优先提供读者实际需要的信息。
- 优先介绍项目现状，不得将计划中的功能描述为已实现功能。
- 以必要信息为主，避免无意义的背景介绍、重复说明和过度细化。
- 优先使用简短说明、命令示例和必要的链接。
- 章节应当有明确的信息目的，不得为了追求内容完整而机械地增加章节。
- 相同信息只应有一个主要维护位置，避免在多份文档中重复维护。
- 不确定的信息必须先核实，不得自行编造。
- 不得因为某项规则重要，就将其纳入到 README。

### 推荐内容范围

根据项目实际情况，README 可以包含：

1. 项目名称与简介：说明项目是什么、解决什么问题。
2. 项目展示：实际运行截图、演示地址或预览入口。
3. 主要功能：介绍已经实现的核心功能。
4. 技术栈：列出主要框架、语言和关键技术。
5. 环境要求：说明运行所需的软件、版本和外部服务。
6. 快速开始：提供依赖安装、环境配置和启动步骤。
7. 项目结构：简要介绍有助于理解项目的主要目录。
8. 相关文档：链接到实际存在且有必要阅读的专项文档。

以上是可选内容范围，不要求每个项目都必须包含全部章节。应根据项目规模、实际需求和读者价值决定是否保留。

### 不应写入 README 的内容

原则上不得将以下内容直接写入 README：

- AI Agent 的行为要求、权限限制和工作流程。
- 详细的代码编写规范、命名规范和架构约束。
- 详细的 UI 设计规范、字体规范、颜色规范和组件样式约束。
- 详细的无障碍实现规则、键盘交互约束和屏幕阅读器规范。
- 具体组件、函数和模块的内部实现说明。
- 开发过程中的临时问题、调试记录和操作日志。
- 已经由其他专项文档完整记录的内容。
- 与项目介绍、使用、运行和参与开发无直接关系的信息。

如果上述内容确实有长期维护价值，应当放入职责合适的专项文档，并在 README 中视需要提供链接。

### README 质量要求

完成 README 修改后，应检查：

- 是否能够让初次接触项目的读者快速理解项目。
- 是否提供了准确、可执行的启动说明。
- 命令、路径、环境变量和链接是否真实有效。
- 是否存在重复、过时、无关或过度细化的内容。
- 是否混入了仅供 Agent 或内部开发流程使用的指令。
- 是否出现了与其他项目文档相互矛盾的说明。

README 应保持精简、清晰、可维护。内容数量不是质量指标，不得以增加章节或文字数量作为文档完善程度的衡量标准。
